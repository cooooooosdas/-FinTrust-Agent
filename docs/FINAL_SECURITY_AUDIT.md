## 二、身份与账户隔离

| 机制 | 实现 | 验证 |
|---|---|---|
| 密码哈希 | PBKDF2-HMAC-SHA256（260k 迭代）+ 随机盐 | ✅ |
| Token 存储 | 服务端仅存 HMAC 摘要 | ✅ |
| 账户归属 | `ensure_account_access` 强制校验 | ✅ 越权返回 403 |
| Agent 工具层归属 | `_assert_account_authorized` 纵深防御 | ✅ |

**实测**：demo_user_1 访问账户 2 → 403；demo_user_2 访问账户 1 → 403；Agent 伪造 account_id=2 → 403。

## 三、三级权限引擎（policy.py，覆盖率 88%）

| 等级 | 触发 | 实测 |
|---|---|---|
| 绿色 | 只读查询 | ✅ |
| 黄色 | 写操作且执行后日累计 ≤ ¥1000 | ✅ 800 元 → 需确认 |
| 红色 | 执行后日累计 > ¥1000 或挂失/改密/敏感词 | ✅ 1500 元 → MFA |
| 阻断 | 日累计 > ¥100,000 | ✅（策略测试） |

**核心保证**：PolicyEngine 只接收业务事实（金额/日累计/收款人属性），不接收 LLM 权限建议。

## 四、MFA 持久化（覆盖率 86%）

- 验证码 `secrets` 生成，仅存 HMAC-SHA256 摘要（`MFA_SECRET_KEY` 环境变量）。
- 挑战绑定 user/account/operation/target，跨交易复用拒绝。
- 默认 300s 有效期，5 次错误锁定。
- **真实进程重启验证**：停进程→重启→原 challenge_id+原验证码验证成功→复用被拒 ✅。

## 六、请求限流（rate_limiter.py，覆盖率 90%）

| 接口 | 限制 | 实测 |
|---|---|---|
| 登录 | 单 IP 10次/分钟 | ✅ 429 |
| 登录失败 | 用户名+IP 5次/15分钟 | ✅ |
| MFA 创建 | 3次/10分钟 | ✅ |
| Agent Chat | 30次/分钟/用户 | ✅ |
| 转账预览/执行 | 10次/分钟/账户 | ✅ |
| 审计查询 | 60次/分钟/用户 | ✅ |

- 限流键 HMAC 脱敏，不保存原始 IP。
- 触发返回 429 + Retry-After + 审计。
- **如实声明**：基于 SQLite 单写者模型，仅适用于单进程竞赛演示，非分布式生产级。

## 七、Prompt Injection 防御

| 攻击向量 | 防御 | 实测 |
|---|---|---|
| 直接注入（忽略规则/伪造管理员） | 意图只做分类，权限由后端判定 | ✅ 未执行转账 |
| 间接注入（恶意收款人名/备注） | 视为不可信业务数据 | ✅ |
| 工具越权（未知工具/伪造 account_id） | 白名单 + 账户归属校验 | ✅ |
| 模型伪造权限（risk=green） | 后端重新判权 | ✅ |

**红队测试 15 例全部通过**。核心边界由"工具白名单 + 身份上下文 + PolicyEngine + 状态机"组成，非正则检测。

## 八、审计完整性（audit_integrity.py，覆盖率 93%）

- 哈希链：`event_hash = HMAC(密钥, previous_hash + 规范化内容)`。
- 密钥 `AUDIT_HMAC_KEY` 环境变量管理，不落库、不入 Git。
- 防篡改触发器：阻止 UPDATE/DELETE 已签名记录。
- 验证工具 `verify_audit_integrity.py`：正常 PASS，篡改/删除/重排/密钥错误均 FAILED 并定位。
- **信任边界（如实声明）**：哈希链+HMAC 可检测篡改，但**不能**声称在 DB 管理员与密钥同时被攻破时仍绝对不可篡改。
