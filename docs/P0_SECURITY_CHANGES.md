# 金枢 FinTrust Agent — P0 安全变更说明

> 阶段：V0.2.0 第二阶段（P0 安全修复）
> 说明：本文件记录本轮对安全机制的变更，供评审与后续维护参考。

---

## 一、权限策略变更（三级权限）

### 变更前
- 主轴 = 单笔金额：¥5000 黄 / ¥50000 红
- 日累计：¥20000 黄 / ¥100000 红线
- 小额转账 → **绿色自动执行**（违反「写操作不能绿色」）

### 变更后
| 等级 | 判定 | 处理 |
|---|---|---|
| 绿色 | 仅只读：余额查询、交易查询、账单分析、理财收益查询、审计查询 | 自动执行 |
| 黄色 | 写操作且**执行后日累计 ≤ ¥1000**（含恰好 1000） | 展示详情 + 用户明确确认 |
| 红色 | **执行后日累计 > ¥1000**；挂失、密码修改等敏感操作 | 模拟 MFA |

**硬规则**：
1. 任何资金写操作**绝不能绿色**（最低黄色）。
2. 日累计是**主要**判定依据。
3. 单笔金额可辅助升红（≥ ¥10000），**不替代**日累计判断。
4. 恰好 1000 属黄色，超过 1000 立即红色。
5. 按交易发生日 + 业务时区（默认 Asia/Shanghai）计算累计。
6. 金额全程整数分。
7. 权限引擎**不接受**前端/LLM 提供的风险等级。

## 二、执行阶段风险重判（核心安全修复）

**变更前**：执行时复用预览快照 `policy_json`，不重算累计。

**变更后**：执行时在 `BEGIN IMMEDIATE` 事务内：
1. 重读账户 → 2. 重算日累计 → 3. 重新 `policy_engine.evaluate()` → 4. 按最新判定处理。

**权限升级保护**：
- 预览黄 → 执行时累计超限 → 升级红色，**不扣款**，持久化 MFA 挑战，返回 428。
- 预览红 → 执行时累计降低 → **不降级**，仍要求 MFA。
- MFA 通过后**再次完整重判**。

---

## 三、并发安全（日累计不穿透）

**变更前**：无行锁，6 笔并发可同时通过同一份旧累计值。

**变更后**：
- `BEGIN IMMEDIATE` 在事务起始获取写锁，串行化并发写（SQLite 单写者模型）。
- 余额扣减用**条件 UPDATE**（`WHERE balance_cents >= :amt`），按受影响行数判断。
- 连接池扩容（size 30 / overflow 30）+ `timeout=30`，消除连接池耗尽导致的 500。

**验收**：20 线程各 ¥200 并发，成功总额 ≤ ¥1000，无 500，余额与流水一致。

---

## 四、幂等机制（用户意图级）

**变更前**：`key = idempotency_key or order_no`，order_no 每次预览不同 → 重复扣款；
前端每次现生成随机键；`begin()` SELECT-then-INSERT 有竞态。

**变更后**：
- 前端一次意图生成**一个稳定 UUID**，预览/执行/重试复用。
- 同键同参 → 首次结果；同键异参 → `IDEMPOTENCY_CONFLICT`。
- `begin()` 捕获 `IntegrityError` 后重查（并发安全）。
- 幂等记录 TTL 清理（3600s），避免 `in_progress` 残留阻塞。
- 服务端「已 executed 幂等返回」兜底，同一工单仅一次成功扣款。

## 五、MFA 安全变更

| 项 | 变更前 | 变更后 |
|---|---|---|
| 随机源 | `random.randint` | `secrets`（CSPRNG） |
| 挂失挑战 | 校验阶段重新 issue 新码 → 恒 422 | challenge_id 持久化复用，不重发 |
| 挑战存储 | 进程内 dict（重启丢失） | 仍进程内（本轮未做持久化，见遗留项） |
| 验证码消费 | 一次性 | 一次性（不变） |

## 六、工单号生成

| 变更前 | 变更后 |
|---|---|
| `TR{时间}{id(decision)%10000}`（内存地址，可冲突） | `TR{时间}{uuid4 hex[:8]}`（全局唯一） |

## 七、数据库配置变更

`app/core/database.py`：
- SQLite `check_same_thread=False`（跨线程复用）
- `timeout=30`（写锁等待）
- `pool_size=30` / `max_overflow=30` / `pool_timeout=60`
